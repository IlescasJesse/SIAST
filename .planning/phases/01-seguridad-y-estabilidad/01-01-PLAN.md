<objective>
Eliminar las tres vulnerabilidades críticas de seguridad relacionadas con el arranque del servidor y la exposición de OTPs: JWT secret hardcodeado, CORS abierto en no-producción, y OTP visible en HTTP response.

Purpose: El servidor actual puede arrancar en producción sin un JWT_SECRET real (usando el fallback "siast_dev_secret" predecible), permite cualquier origen CORS en entornos no-prod, y expone el código OTP directamente en la respuesta HTTP cuando WhatsApp falla. Estos tres problemas comprometen la autenticación completa del sistema.

Output: API que no arranca sin las variables de entorno obligatorias, CORS configurado con allowlist explícita, OTPs nunca visibles en HTTP response.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → API (auth endpoints) | Requests no autenticados que inician flujo OTP o login de staff |
| API → WhatsApp Web.js | Canal de entrega de OTP — puede fallar sin aviso |
| API → env runtime | Variables de configuración críticas (JWT_SECRET, CORS_ORIGINS) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | apps/api/src/config/jwt.ts | mitigate | Eliminar fallback "siast_dev_secret" — cualquier JWT firmado con ese secret predecible puede ser forjado por quien lea el código fuente. Mitigación: throw si JWT_SECRET falta en env |
| T-01-02 | Elevation of Privilege | apps/api/src/index.ts (CORS) | mitigate | CORS con `origin: true` permite cualquier origen hacer requests autenticados cross-origin. Mitigación: allowlist explícita via CORS_ORIGINS env var |
| T-01-03 | Information Disclosure | apps/api/src/services/whatsapp.service.ts | mitigate | devCodigo en HTTP response expone el código OTP — cualquiera que intercepte el response puede autenticarse sin el teléfono del empleado. Mitigación: eliminar devCodigo del retorno; en prod lanzar 503 |
| T-01-04 | Tampering | apps/api/src/services/otp.service.ts | mitigate | Math.random() no es CSPRNG — un atacante con acceso al timestamp puede predecir los códigos OTP. Mitigación: crypto.randomInt(100000, 999999) (Node.js built-in CSPRNG) |
| T-01-05 | Denial of Service | apps/api/src/index.ts (startup) | accept | Si CORS_ORIGINS o JWT_SECRET no están en env, el servidor no arranca — esto es intencional. El riesgo es un despliegue fallido, no un ataque. Mitigación en proceso operacional: .env.example documenta las vars. |
</threat_model>
